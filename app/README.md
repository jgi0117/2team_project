# Dash 앱 작업 위치

이 디렉토리는 아직 실행 가능한 앱을 포함하지 않습니다.

- `pages/`: 설비 현황, Azure PdM 고장예측, 조달·정비 비용 비교, 데이터 조회, 보고서 요약 화면.
- `components/`: 기간·설비·예측기간 필터, KPI 카드, 표와 그래프 등 공통 UI.
- `assets/`: CSS와 이미지.

운영 화면에서는 부품을 선택하면 기준정보의 조달기간·정비 준비시간과 조회 기준일의 가용 예비재고를 읽기 전용으로 표시합니다. 조달기간과 예비재고에는 드롭다운을 두지 않습니다. 목표 예비재고는 부품별 설정값이며, 현재 가용재고는 입고·사용·예약에 따라 변하는 조회값입니다. 초기 재고별 비용 비교는 별도 분석 시나리오에서 수행합니다.

부품 정보에는 `입고 후 사용 가능 기간`과 제약 사유를 표시합니다. 예: `30일 이내 공정 투입 · 산화 방지`(가정). 재고 표에는 로트별 수량·실제 입고일·사용 기한·남은 일수·상태를 표시합니다. 같은 부품이라도 입고일이 다르면 기한을 따로 계산합니다. 기한 초과·예약·격리 수량은 가용재고에서 제외하고, 기한 정보가 없으면 `기한 확인 필요`로 표시하여 자동 배정하지 않습니다.

대응 계획에서는 공정 투입 예정일이 준비 완료 이후이면서 사용 기한 이내인지 확인합니다. 기한이 빠른 가용 로트부터 배정하고, 입고 전 예상 기한은 실제 입고 후 갱신합니다. 세부 계산과 화면 예시는 [데이터와 구현 계획](../data/readme.md)을 따릅니다.

분석 로직은 `src/`에 구현하고, 앱은 고장예측과 비용 시뮬레이션 결과를 읽어 표시합니다. CSV 업로드·검증, DataTable, 필터, 결과 다운로드를 구현하며 필터 변경 시 KPI와 그래프가 일관되게 갱신되는지 검증합니다.

앱 진입점을 구현한 뒤 루트 README에 실제 실행 명령을 추가합니다.
