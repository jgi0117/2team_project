# 가상 운영 데이터

## 협력사 데이터

대시보드에는 부품별 협력사, 현재 가용재고, 표준 납기를 표시합니다. 부품마다 협력사 한 곳만 연결하며 대체 업체와 별도 공급 조건 파일은 사용하지 않습니다.

| 화면 항목 | 데이터 연결 |
| --- | --- |
| 협력사 | `part_master.supplier_id` → `suppliers.supplier_id`의 `supplier_name` |
| 현재 재고 | 조회 시점의 가용 로트 수량 합계. 설비 100대가 공유하는 부품별 중앙창고 재고 |
| 표준 납기 | `part_master.lead_time_days` |

`suppliers.csv`에는 협력사 ID, 가상 업체명, 담당 부서(`contact_department`), 전화번호(`contact_phone`), 이메일(`contact_email`), 출처를 저장합니다. 전화번호의 `XXXX`는 가상 연락처임을 나타내고, 이메일은 발송되지 않는 `example.invalid` 도메인을 사용합니다. 실제 발주 전에 실제 업무 연락처로 교체해야 합니다. comp1·comp3은 가상협력사 A(SUP-001), comp2·comp4는 가상협력사 B(SUP-002)와 연결했습니다. 표준 납기는 각각 7·35·14·21일이며, 이미지의 30일은 화면 예시이므로 실제 설정값을 변경하지 않았습니다.

현재 재고는 고정 마스터 값으로 복사하지 않습니다. 최종 스냅샷에서는 준비 완료, 품질 available, 사용기한 이내인 로트의 보유량에서 예약량을 뺀 값을 합산합니다. 과거 시점에는 그때까지의 inventory_movements를 재생해야 합니다. 재고 0은 오류가 아니라 실제 계산 결과일 수 있습니다.

기존 발주 169건의 supplier_id도 같은 협력사에 연결되어 있습니다. 기존 발주일·예정일·실제 입고일·수량·상태는 유지했으며, 협력사를 고려해 시뮬레이션을 다시 실행한 결과는 아닙니다. 대체 업체와 업체별 가격 비교는 이번 범위에서 제외했습니다.

**예측 결과를 발주·정비 판단에 연결하기 위한 합성 시나리오입니다.** 실제 부품 사양이나 공장의 측정값이 아닙니다. 모든 행의 `value_source`에 가정임을 표시했으며 실제 이름이 없는 부품은 comp1~comp4로 유지했습니다.

## 수치의 설정 근거

2015-01-01 06시부터 2015-04-01 06시 직전까지 **90일간의 교체 이력만** 사용해 초기 수요를 계산했습니다. 이후 정보로 초기 재고나 발주 기준을 최적화하지 않았습니다.

| 부품 | 기준기간 교체 건수 | 일평균 수요 | 조달기간 | 정비 준비 | 목표 가용재고 | 입고 후 사용 가능 기간 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| comp1 | 166 | 1.84개 | 7일 | 1일 | 19개 | 180일 |
| comp2 | 158 | 1.76개 | 35일 | 7일 | 25개 | 30일 |
| comp3 | 152 | 1.69개 | 14일 | 2일 | 19개 | 90일 |
| comp4 | 162 | 1.80개 | 21일 | 3일 | 22개 | 120일 |

재고는 **설비 100대가 공유하는 중앙창고 수량**입니다. 목표재고는 `ceil(일평균 수요 × (7일 점검주기 + 안전일수))`이며 안전일수는 각각 3·7·4·5일입니다. 초기 보유량은 목표재고와 같고 진행 중 주문도 설정했습니다. 초기 로트의 나이와 기존 주문은 시작 시점의 가정이며 과거 실제 발주 의사결정을 입증하는 기록이 아닙니다.

조달기간은 단기·중기·장기 대응을 비교하기 위한 가정입니다. comp2는 조달 35일과 준비 7일이 필요하고, 입고 후 사용 기한은 30일입니다. **준비 완료 후 투입 가능한 기간은 23일**로, 늦은 발주와 너무 이른 입고를 모두 평가할 수 있습니다. 산화 이슈 역시 가정입니다.

구매단가는 comp1 18만원, comp2 250만원, comp3 65만원, comp4 120만원으로 서로 다른 교체 부품을 가정했습니다. 시장 조사 가격은 아닙니다. 예방·긴급 작업비는 구매비와 분리했고 긴급 작업비는 예방 작업비의 3배입니다. 보유비는 구매단가의 연 20%를 365일로 나눈 값, 폐기 처리비는 구매단가의 1%, 긴급 운송 할증은 구매단가의 25%입니다. 정지 손실은 150만~500만원/일의 가정입니다. 구매비에 반영한 부품값을 폐기 시 다시 합산하지 않습니다. 비용 평가 시 단가의 민감도를 별도로 확인합니다.

## 생성 방식

- 운영기간은 2015-04-01 06시~2016-01-01 06시입니다. 원본과 같은 시간축이며 시간대는 임의 변환하지 않습니다.
- Azure 정비 이벤트가 발생한 시점에 해당 설비·부품의 1개 교체 수요가 관측되었다고 가정합니다. 미래 수요를 발주 입력에 넣지 않습니다. 생성기는 `PdM_failures.csv`와 센서값을 읽지 않습니다.
- 7일마다 당시까지의 최근 90일 수요로 발주합니다. 목표 포지션은 `ceil(일평균 수요 × (조달일수 + 준비일수 + 7 + 안전일수))`입니다. 현재 유효 보유량과 진행 주문에서 대기 수요를 뺀 값이 목표보다 작으면 차이만큼 주문합니다. 향후 만료될 재고까지 선제적으로 제외하는 최적화는 아직 적용하지 않았습니다.
- 납기는 70% 확률로 예정일 도착, 20% 확률로 1~5일 지연, 10% 확률로 7~14일 지연을 가정합니다. 미래 수요·고장에 맞춰 지연을 만들지 않습니다. 실제 납기 결과는 입고 시점에만 공개합니다.
- 신규 로트의 5%는 품질 확인으로 입고 후 3일간 격리합니다. 검사와 정비 준비는 입고 시점부터 병행하며 두 조건을 모두 만족해야 출고합니다.
- 투입 가능한 로트 중 사용 기한이 빠른 순서로 사용합니다. 재고 부족·미준비·격리 시 수요를 대기시킵니다. 기한이 지나면 즉시 사용을 막고 7일 후 잔여 수량을 폐기합니다.
- 원본 교체 날짜는 수정하지 않습니다. 수요 관측은 `source_event_at`, 가상 공급 충족은 `completed_at`으로 구분합니다. `planned_at`은 이번 정책의 수요 접수 시점이며 미리 예측한 정비 계획일이 아닙니다.

기준 정책의 대기 수요는 comp1·2·3·4 각각 38·91·74·23건이며 comp2의 기한 초과 폐기는 3개입니다. 실제 공장이나 모델 성능이 아닌 시뮬레이션 결과입니다. 준비 대기를 곧바로 설비정지 시간으로 해석하지 않습니다.

## 과거 시점 조회

전체 CSV에는 나중에 발생한 입고·정비 결과가 들어 있으므로 과거 시점의 예측·판단에 그대로 조인하면 정보 누출이 발생합니다.

```python
from src.maintenance_planning.operations_snapshot import snapshot

state = snapshot("2015-06-01 06:00:00")
available_comp2 = sum(
    lot["quantity_available"]
    for lot in state["inventory_lots"] if lot["component"] == "comp2"
)
```

이 함수는 그 시점까지의 재고 이벤트만 합산하고 미래 실제 입고일·정비 완료일·사용 로트를 숨깁니다. 미래 입고 **예정일**은 당시 알 수 있는 정보이므로 유지합니다. 재고는 준비·기한·품질 조건을 만족한 `quantity_available`을 사용합니다. 지원 기간 밖 조회는 오류로 처리합니다.

**고장예측 학습에는 원본 센서·오류·정비 이력을 사용합니다.** 가상 정비 완료시점은 원본 센서 변화와 인과적으로 연결되지 않아 원본 교체 이력이나 고장 정답을 대체하지 않습니다. 운영 데이터는 고장예측의 정확도를 인위적으로 높이는 용도가 아니라 예측 결과에 따른 점검·발주·정비 결정을 평가하는 용도입니다. 정책별 재고·완료 기록은 각 정책으로 다시 시뮬레이션해야 합니다.

기본 실행은 생성 CSV와 보고서를 다시 씁니다. `--output-dir`로 별도 경로를 지정할 수 있으며 원본은 수정하지 않습니다. `--end "2015-06-01 06:00:00"`으로 과거 시점까지만 재생할 수 있습니다. 시드와 설정이 같으면 같은 결과를 생성합니다.

검증 항목은 로트 수량 보존·음수 방지, 주문·출고·정비 참조 관계, 기한·준비시간 준수, 재현성, 과거 시점 재생 일치, 미래 수요를 제거해도 과거 결과가 동일한지입니다.
