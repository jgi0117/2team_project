# F04 · 대응 이력 및 성과 추적

## 목적

원본 정비 이벤트 중 긴급 교체와 예방 교체를 구분해 월별 예방 대응률을 제공하고,
운영 기록의 최근 조치 내역을 확인합니다. 가상 조달·정비 시뮬레이션 결과를 원본
고장예측 데이터와 혼합하지 않습니다.

## 예방 대응률 계산

이벤트 정의는 `src/common/labels.py`의 `load_events()`를 따릅니다. PdM 정비 기록의
각 이벤트를 같은 `machineID` 및 부품의 고장 기록과 날짜 기준으로 연결합니다. 두 기록
날짜가 1일 이내로 가장 가까우면 긴급(`is_emergency=1`), 매칭되지 않으면 예방
(`is_emergency=0`)으로 표시합니다.

`예방 대응률 = 해당 월의 예방 교체 건수 / 해당 월의 전체 교체 건수`

조회 기준일이 속한 연도의 1월 1일부터 기준일까지 이벤트를 자르고 월별로 집계합니다.
따라서 해당 월은 기준일까지만 포함될 수 있습니다. 분모가 되는 전체 교체에는 긴급 및
예방 이벤트가 모두 포함됩니다.

## API와 결과

```python
from src.F04 import build_tracking

tracking = build_tracking("2015-12-21")
print(tracking["history"])
print(tracking["recent_actions"])
```

`as_of` 생략 시 최신 예측 시점이 기준입니다. 결과는 기준일, 모델 버전, 예측 행 수,
월별 이력, 최근 조치 목록을 포함합니다. 최근 조치는 가상 운영 데이터의 `planned_at`이
기준 시점 이하인 기록 중 최근 5건입니다. 예방 대응률과 이 운영 기록은 서로 다른
출처/계산이므로 직접적인 인과관계로 읽지 마세요.

## 해석 시 주의

예방 여부는 원본 고장 기록과 정비 기록의 날짜 매칭 정의에 따른 분류입니다. 실제 정비
계획의 품질, 모델 경보의 적중률 또는 정비가 고장을 방지한 인과 효과를 직접 측정하지
않습니다. 월간 건수가 적으면 비율 변동이 클 수 있습니다. 운영 내역은 합성 시나리오이며
모델 학습 또는 원본 이력 대체 용도가 아닙니다.
