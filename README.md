# 설비 고장 예측 기반 정비 의사결정 지원 시스템

고장을 미리 예측해 부품 조달과 정비에 필요한 시간을 확보하고, 설비보전 담당자의 점검·발주·정비 시점 결정을 지원합니다.

기준 문서: [2조 프로젝트 기획서](docs/2조_프로젝트_기획서.pdf). 기존 에너지·AI4I 설계와 이전 목업은 이번 구조에서 제외했습니다.

## 기획 방향

| AS IS: 고장 예측 중심 | TO BE: 대응 시점 중심 |
| --- | --- |
| 고장 3일 전 경고라도 조달에 6주가 걸리고 재고가 없으면 사전 정비가 어려움 | 재고·입고일·정비 준비시간을 반영해 필요한 선행시간 평가 |
| 너무 이른 발주는 장기 보관·폐기 부담, 늦은 발주는 긴급 대응 필요 | 조달·보유·긴급 대응 비용을 운영조건으로 비교하여 발주 시점 검토 |
| 이른 경고의 불확실성과 사용 기한 초과 위험 | 예측기간별 성능을 검증하고 사용 기한 내 투입 가능한 일정 판단 |

위 비교와 화면의 숫자는 기획 시나리오이며 실제 성능 결과가 아닙니다. 비용 비교는 기획서에 포함된 운영 판단 기능으로 관리합니다.

## 담당자가 매일 확인할 정보

- 오늘 우선 점검할 설비와 위험 부품
- 고장까지 예상 시간 또는 기간별 고장 위험
- 필요한 부품의 조달기간, 가용재고, 입고 예정일
- 권장 발주 마감일과 대응 여유, 사용 기한

## 기능별 작업 디렉토리

```text
src/
  common/                 공통 경로, 식별자, 데이터 계약
  data_pipeline/          원본 검증, 전처리, 특징·정답 생성
  failure_prediction/     부품별 고장예측, 시간순 평가
  maintenance_planning/   재고·조달·사용 기한, 발주·정비 판단
  dashboard/              메인 KPI, 우선 점검 목록, 캘린더
  equipment_detail/       설비·부품 상세, 대응 현황, 정비 기록
  statistics/             설비·부품별 통계와 추이
data/
  raw/azure_pdm/          원본 CSV 5종, Git 추적
  operations/            재현 가능한 가상 운영 데이터와 생성 설정
  processed/             전처리·예측·정비 계획 결과 저장 위치
docs/
  2조_프로젝트_기획서.pdf
  DATA_CONTRACT.md        기능 간 입력·출력 규약
requirements.txt         Python 분석 기본 의존성
```

각 기능의 범위와 입출력은 해당 `src/<기능>/README.md`를 확인합니다. 가상 운영 데이터 생성기와 과거 시점 조회 기능을 구현했으며, 고장예측 모델과 UI는 아직 없습니다. UI 프레임워크는 구현 단계에서 결정합니다.

## 데이터와 연결 원칙

[데이터 안내](data/README.md), [운영 데이터 양식](data/operations/README.md), [공통 데이터 계약](docs/DATA_CONTRACT.md)을 기준으로 작업합니다.

Azure PdM은 100대 설비의 공개 시뮬레이션 데이터입니다. 원본은 실제 공장 실측 데이터가 아닙니다. 부품은 `comp1`~`comp4`를 다루며 실제 부품명은 미제공입니다. 조달·재고·입고·사용 기한·비용은 별도 가상 운영 데이터로 구축했습니다. 2015년 1~3월 교체 수요로 초기 재고를 설정하고 4월 이후를 재생합니다. 모든 값에 가정임을 표시했으며, 과거 판단에는 `operations_snapshot.snapshot()`을 사용해 미래 입고·완료 정보를 제외합니다.

기간 내 고장 확률은 정확한 고장일이나 보장된 잔여수명이 아닙니다. 정비 파일의 교체일을 부품 입고일로 해석하지 않습니다. 과거 이력만으로 예측 입력을 만들고 미래 정보는 정답 생성에만 사용합니다.

## 협업과 실행 준비

`main`은 README만 유지합니다. `GJ`, `GE`, `JH`는 같은 기능별 구조를 공유하며 각자 본인 브랜치에서 작업합니다. 팀에서 기능 담당을 정한 후 해당 폴더를 중심으로 수정합니다. 공통 데이터 계약 변경은 다른 기능 담당자와 먼저 맞춥니다.

```powershell
git switch GJ  # 본인 작업 브랜치로 변경
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

현재 원본 및 가상 운영 데이터, 생성·검증·시점별 조회 코드가 있습니다. 실행 앱·학습 모델·모델 평가 결과는 없습니다. 재현 방법과 운영 시뮬레이션 결과는 [운영 데이터 안내](data/operations/README.md)에 정리했습니다. 의존성 버전은 개발 환경 검증 후 고정합니다. 데이터는 Git으로 관리하며, 원본은 수정하지 않습니다.
