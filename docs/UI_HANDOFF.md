# 설비보전 대시보드 UI 인수인계서

이 문서는 2team_project의 **예지보전 Dash 대시보드 UI**가 어떻게 만들어졌는지 정리한 것입니다.
이 저장소를 처음 보는 사람이나 AI가 이 문서 하나만 읽고 이어서 작업할 수 있게 쓰는 것이 목표입니다.

- 브랜치: UI 작업은 `UI` 브랜치에서 하고, 완료되면 `GE` 브랜치에 그대로 반영합니다(fast-forward).
- 기준 화면: 발표용 1920×1080.
- 기본 기준일: `2015-10-05`. 고장 예측은 이날부터 매주 월요일에 한 번씩 만들어져 있습니다.
- 실행: `.venv/Scripts/python.exe -m src.ui.app` → http://127.0.0.1:8050

---

## 1. 이 대시보드가 하는 일

공장 설비 100대(부품 comp1~comp4)의 **고장 위험**과 **센서 이상**을 보여 주고, 정비 담당자가 다음 네 가지를 결정하도록 돕습니다.

- 오늘 무엇을 먼저 확인할지
- 부품을 언제 발주할지
- 어느 협력사에 몇 개를 발주할지
- 지금까지 얼마나 미리 대응했는지

화면에 나오는 숫자는 모두 **실제 데이터나 팀원의 기능 코드 계산 결과**입니다. 가짜 예시 데이터는 쓰지 않습니다.
예외는 두 가지뿐이며, 모두 가정이라고 명시해 두었습니다.

- 사이드바의 로그인 사용자 `홍길동`
- 가상 운영 데이터: 재고, 협력사, 비용

## 2. 폴더 구조

```

├── pages/
│   ├── main.py            # 메인화면
│   ├── detail/page.py     # 설비화면 (URL: /detail?machine=32)

    ├── 00_tokens.css      # 색·글꼴·반경·그림자 토큰 (모든 색은 여기서)
    ├── 20_main.css        # 메인화면 (클래스 접두어 mn-)
    ├── detail/detail.css  # 설비화면 (.page-detail 안, 접두어 dt-/f06-/f07-/hs-)
```

## 3. 화면별 구성

### 3.1 메인화면 (`/`)

위에서부터 아래 순서입니다.

1. **AI 한 줄 요약**: 가장 먼저 볼 설비와 그 설비로 가는 링크.
2. **오늘 요약 + To-Do 달력**: 이 두 영역이 같은 줄에 나란히 있습니다.
   - 오늘 요약 카드는 4장입니다: 경고 설비, 교체기한 임박, 기한 초과, 이번 주 발주 필요.
   - 카드는 같은 크기로 세로로 쌓이고, 숫자 줄이 모두 맞춰져 있습니다.
   - 카드를 누르면 상세 목록 창이 뜹니다.
   - 달력은 화면에서 유일하게 떠 있는 흰 판(hero)입니다. **눈이 가장 먼저 가야 하는 요소**입니다.
   - 달력 칩은 부품 교체(남색)와 이상 신호(노랑)로 나뉘고, 우선순위 번호가 붙습니다.
   - 하루에 보이는 칩 수는 설정할 수 있습니다. 넘치는 칩은 `+N건 더 보기`로 묶입니다.
   - `우선 확인 TOP5 보기` 토글을 누르면 달력 옆에 TOP5 패널이 열리고, 정렬 기준을 고를 수 있습니다.
   - 달력 칩과 TOP5 카드는 같은 색과 같은 번호로 1:1 대응합니다.
3. **고장 확률 급상승 알림 | 재고 × 위험 교차**: 두 영역이 나란히 있습니다.
   - 급상승 알림은 막대그래프 TOP3이고, 막대를 누르면 해당 설비 화면으로 갑니다.
   - 재고 × 위험 교차는 표입니다. comp2 옆의 `안전재고 ⓘ`를 누르면 안전재고 설명 창이 뜹니다.
4. **과거 대응률**: 스크롤해야 보이는 영역입니다. 월별 예방 대응률 선 그래프와 "미리 대응 N건 / 대응 필요 M건"이 있습니다.
   - 사용자가 발주를 요청하면 그 기록이 누적되어 반영됩니다.
   - 월별 절감액과 누적 절감액은 사용자 요청으로 삭제했습니다.

1920×1080 첫 화면은 급상승 알림과 재고 × 위험 교차 근처에서 끝나도록 맞췄습니다.

### 3.2 설비화면 (`/detail?machine=N`)

"희미한 설비 도면을 캔버스 전체에 깔고, 정보를 그 위에 띄운다"는 방향입니다.
흐름은 **상태 → 위치 → 이유 → 근거 → 행동** 순서입니다.

1. **상단 캔버스**
   - 왼쪽에는 설비 번호, 위험 상승 예상 D-day, 72시간 센서 이상 신호, AI 종합 진단이 있습니다.
   - 오른쪽 도면 위에는 부품별 말풍선이 떠 있습니다. 말풍선에는 D-day와 판정이 나오고, `발주 검토 →`를 누르면 해당 부품의 발주 검토로 스크롤됩니다.
   - 도면 위 토글로 `부품 위치`와 `4개 부품 기간별 위험`을 전환합니다.
   - 오른쪽 위에는 `발주 담기 N건`과 `교체 이력` 버튼이 있습니다. 교체 이력 버튼을 누르면 해당 섹션으로 자동 스크롤됩니다.
2. **센서 이상 근거**
   - 그래프 두 개가 위아래로 있습니다.
     - ① 선택한 센서값과 IQR·3σ 기준선
     - ② 설비 전체 IF 이상 점수
   - 두 그래프는 번호 태그, 서로 다른 배경색(남색 톤 / 노랑 톤), 나눠 둔 범례로 구분합니다.
   - 오른쪽에는 IF 점수 카드와 센서별 판정 표가 있습니다.
3. **발주 시점 · 비용 검토**
   - 부품별 접기/펼치기(아코디언)입니다. 펼치면 세 부분이 보입니다.
     - 발주일별 기대 총비용 곡선
     - 발주·재고 정보
     - 발주 시나리오 비교: 오늘 / 1주 뒤 / 2주 뒤
   - `발주 목록 담기`를 누르면 협력사를 고르고 수량을 정해 장바구니에 담습니다.
   - **comp2는 비용 곡선 대신 안전재고 설명과 보충 발주 버튼**을 보여 줍니다. 이유는 5장에 있습니다.
4. **교체 이력**
   - 부품별 한 줄 타임라인입니다. 기간은 12개월이 기본이고 설정에서 바꿀 수 있습니다.
     - ● 표시는 예방 교체입니다.
     - 빨간 ✕ 표시는 고장 후 교체입니다.
     - 줄 오른쪽에 마지막 교체가 며칠 전인지 나옵니다.
   - 오른쪽에는 조치 기록 전체 표가 있고, 10건씩 페이지로 넘깁니다.

### 3.3 통계화면 (`/statistics`)

- 맨 위에 "이 화면이 무엇을 보는지" 한 줄 설명이 있습니다.
- **설비별 이상 위험**: 1시간 단위 IF 이상 점수를 설비 100칸 히트맵으로 보여 줍니다. 오른쪽에 관측 시각이 나옵니다.
- **향후 N일 설비 위험 분포**: 일 단위 예측입니다. 부품 4개 점수 중 최댓값을 보여 주고, 7일 / 14일 / 42일을 전환할 수 있습니다.
- 칸을 누르면 해당 설비 화면으로 이동합니다.
- **히트맵 색상은 바꾸지 않기로 했습니다.** 사용자가 요청한 사항입니다.

### 3.4 발주화면 (`/order`)

- 설비화면에서 담은 발주 목록을 **부품별로 모아서** 보여 줍니다.
- 이 화면에서 수량과 협력사를 확정하고 발주 요청을 보냅니다.
- 요청할 때 TOP5에 같은 설비·부품이 있으면 To-Do에서 완료 처리할지 묻습니다.
- 사이드바 메뉴의 뱃지는 담긴 건수입니다.

### 3.5 설정 창 (사이드바 로고의 ⚙ 버튼)

탭은 세 개입니다.

| 탭 | 내용 |
|---|---|
| 로그인 기록 | 접속 시각·사용자·소속·권한. **지금은 브라우저에만 저장**(`store-login-log`). 로그인·DB가 생기면 서버 기록으로 교체 |
| 완료 기록 관리 | To-Do에서 완료 처리한 항목 `복구`(다시 To-Do·TOP5에 나타남), 발주 요청 `요청 취소` |
| 기본 설정 | 아래 표. 저장하면 바로 화면에 반영(`store-settings`, 브라우저 로컬 저장) |

| 분류 | 항목 | 기본값 |
|---|---|---|
| 메인화면 | TOP5 기본 정렬 기준 | 설비 위험도 높은 순 |
| 메인화면 | To-Do 이상 신호 기준 (IF 점수) | 0.50. To-Do 목록에만 적용되고, 설비화면의 IF 판정은 모델 기준을 그대로 씀 |
| 메인화면 | 달력 하루 표시 건수 | 2건 |
| 메인화면 | 과거 대응률 기본 기간 | 최근 6개월 |
| 설비화면 | 센서 이상 근거 기본 센서 | 진동 |
| 설비화면 | 발주 마감 기준 (늦을 확률 허용치) | 20% |
| 설비화면 | 교체 이력 기간 | 12개월 |
| 통계 | 히트맵 기본 예측기간 | 7일 |

항목을 추가하는 방법은 다음과 같습니다.

1. `settings.py`의 `DEFAULTS`와 `SPEC`에 한 줄씩 추가합니다.
2. 그 값을 쓰는 화면에서 `merged(settings)["키"]`로 읽습니다.

## 4. 디자인 규칙

- **글꼴**: NanumSquare Neo. 저장소 안에 포함되어 있어 오프라인 발표에서도 그대로 나옵니다.
- **색**: 남색(`#000814`, `#001d3d`, `#003566`)이 구조를 잡고, 노랑(`#ffc300`, `#ffd60a`)은 강조에만 씁니다.
  - 빨강은 위험, 초록은 좋음을 뜻하는 상태색으로만 추가해서 씁니다.
  - 모든 색은 `00_tokens.css`의 CSS 변수(`--ui-navy-700` 등)로 씁니다.
- **카드 남발 금지**: 섹션은 배경에 녹이고, 구분은 남색 세로 막대 제목, 얇은 구분선, 여백으로 합니다.
  - 카드는 KPI처럼 필요한 곳에만 씁니다.
  - 떠 있는 흰 판은 메인 달력 하나뿐입니다.
- **제목**: 이모지를 쓰지 않습니다. 기획 코드(F01, NEW 같은 것)도 화면에 쓰지 않습니다.
- **중복 금지**: 같은 정보를 두 컴포넌트에 반복하지 않습니다. 다른 관점이 필요하면 토글이나 탭으로 보여 줍니다.
- **반응형**:
  - 브레이크포인트는 992px, 576px입니다. 메인은 1500px, 1200px에서도 재배치됩니다.
  - 고정 px 대신 `clamp()`, `%`, `aspect-ratio`를 씁니다. `float:right`는 쓰지 않습니다.
  - 달력 칸은 컨테이너 쿼리를 씁니다. 칸이 좁아지면 `+N건 더 보기`가 `+N`으로 줄고, 부품명을 숨깁니다.
- **스타일 위치**: 인라인 스타일 대신 CSS 클래스와 토큰을 씁니다. 사용자가 나중에 직접 다듬기 쉽게 하려는 것입니다.
- **참고 이미지**: 사용자가 주는 참고 이미지는 "어떤 형태의 차트인지"만 참고합니다. 색과 스타일은 항상 우리 톤으로 만듭니다.

## 5. 중요한 결정과 이유

| 결정 | 이유 |
|---|---|
| 위험 점수는 **상대 위험 점수**로 표시하고 확률이라고 부르지 않음 | 모델 점수가 보정(calibration)되지 않아 절대 확률이 아님. 화면에 AUC·threshold 같은 전문용어도 쓰지 않음. (단, 메인 섹션 제목 "고장 확률 급상승 알림"은 사용자 요청으로 그렇게 표기하고, 축·설명은 "위험 점수") |
| **comp2는 예측을 채택하지 않고 안전재고로 대응** | 42일(조달 35 + 준비 7) 기준 모델 성능이 무작위와 비슷함(위험 상위 10%의 실제 고장률이 평균의 1.03배, AUC 0.62). 고장이 흔하고(42일 동안 설비 31%) 조달이 길어서 조짐을 보고 주문하면 늦음. 그래서 설비별 발주 시점 계산은 의미가 없고, 공용 창고에 목표 재고(25개)를 유지함. 화면에서는 회색 "안전재고" 뱃지와 설명 창으로 안내 |
| 발주 비용 곡선은 **기대 비용** 방식 | 필요 시점을 한 날짜로 두면 곡선이 직선이 되어 의미가 없었음. 모델의 위험 상승 구간(from/mid/to)으로 필요 시점 분포(삼각분포)를 만들고, 이르면 보관비(+사용 기한 초과 시 폐기), 늦으면 긴급 인건비·운송 할증·설비 정지 손실을 기대값으로 더함. 보관비가 연 20%로 작아서 이른 쪽은 완만하고 늦은 쪽이 가파른 게 정상 |
| 발주 마감 = 늦을 확률이 허용치(기본 20%) 이하인 마지막 날 | 설정에서 조절 가능 |
| 진동 그래프와 IF 그래프를 **합치지 않음** | 단위가 달라 이중 축을 쓰면 착시가 생김. 대신 같은 시간축으로 위아래 정렬, 마우스를 올리면 두 값을 같이 표시, IF 경고 시각은 두 그래프에 같은 빨간 띠 |
| 1억 이상 금액은 억 단위 | 큰 숫자 가독성 |
| 가상 협력사 C(긴급대응팀) 추가 | 긴급 발주 시나리오용. `data/operations/suppliers.csv`, `supplier_terms.csv`에 가정 데이터로 명시 |
| 데이터(`data/`, `models/`, `outputs/`)도 UI 브랜치에 포함 | 발표 PC에서 바로 실행되도록 |

## 6. 팀 코드 규칙

- `dash.Dash()`는 `src/ui/app.py`에서만 만듭니다. 각 화면은 `@callback`을 씁니다.
- 콜백 하나에 Output 하나가 원칙입니다. 여러 콜백이 같은 Output을 쓰면 `allow_duplicate=True`를 붙입니다.
- 파일 경로는 `src/common/paths.py`에서 가져옵니다.
- CSV는 한 번만 읽거나 `lru_cache`로 캐시합니다.
- **컴포넌트 ID는 되도록 바꾸지 않습니다.** 팀원의 콜백이 ID에 연결되어 있기 때문입니다.
  - 새 ID는 영역 접두어를 따릅니다: `mn-`(메인), `f05-~f08-`·`dt-`·`hs-`(설비), `sb-`(사이드바), `st-`(설정), `od-`(발주), `store-`(공용 저장소).
- **동적으로 생기는 버튼은 일반 Input으로 쓰지 않습니다.**
  - 그렇게 하면 "nonexistent object" 에러가 납니다.
  - 패턴 매칭 ID(`{"type": ..., "key": ALL}`)를 쓰거나, 버튼을 레이아웃에 고정으로 둡니다.
- 전역 상태는 `app.py`의 Store에 둡니다.

  | Store | 저장 위치 | 내용 |
  |---|---|---|
  | `store-as-of` | session | 기준일 |
  | `store-todo-dismissed` | | 완료 처리 목록 |
  | `store-order-log` | | 발주 요청 기록 |
  | `store-order-cart` | | 장바구니 |
  | `store-order-basket` | | 발주 목록 |
  | `store-settings` | local | 기본 설정 |
  | `store-login-log` | local | 로그인 기록 |

- 설정 창처럼 여러 화면에서 쓰는 팝업은 **루트 레이아웃**에 둡니다. 사이드바 안에 두면 화면을 다시 그릴 때 닫혀 버립니다.

## 7. 검증 방법

작업이 끝나면 아래 순서로 확인했습니다.

1. **단위 테스트**: `PYTHONPATH=. .venv/Scripts/python.exe -m unittest discover -s tests`. 현재 47개가 통과합니다.
2. **콜백 점검**: 화면마다 콜백의 Input/Output ID가 실제 레이아웃에 있는지 확인합니다. 문제 0건이어야 합니다.
3. **콘솔 에러**: 디버그 모드로 띄운 뒤, 헤드리스 Edge(`--enable-logging=stderr --dump-dom`)로 네 화면의 콘솔 에러를 확인합니다. 0건이어야 합니다.
4. **클릭 흐름**: `/_dash-update-component`에 직접 요청을 보내 확인합니다. 대상은 설정 저장·되돌리기, 복구, 요청 취소, 안전재고 창, 교체 이력 스크롤입니다.
5. **화면 캡처**: 헤드리스 Edge `--screenshot`으로 1920×1080, 1440, 1366, 1280, 1100 폭을 찍어 눈으로 확인합니다.
   - 라벨 겹침·잘림, 칩이 칸 밖으로 넘치는지를 봅니다.
   - 펼쳐진 상태를 봐야 하면 레이아웃을 바꿔 띄운 미리보기 서버를 따로 씁니다.
